# BLACK Status Report

Verified against the current source tree (Phase 1 of the honesty/security
cleanup). This replaces the earlier audit, which listed capabilities that had
since been implemented as "fiction."

## Performance

- Process model: 1 main + N renderer processes (1/tab, site isolation); renderer
  sandbox active (no `--no-sandbox`).
- Memory: ~523 MB for 3 real tabs (main 271 + ~96 + ~96 + ~59). Idle CPU near
  zero (~2% of one core over 15 s).
- On par with real browsers for this workload; it is Chromium (V8 + Blink) under
  a Safari skin, not WebKit.

## Known Smoothness Hitches (code audit)

- Tab Overview does a synchronous `view->grab()` per tab when opened.
- `QGraphicsDropShadowEffect` on the active tab forces per-frame software
  re-rendering.
- `WA_TranslucentBackground` frameless window puts the whole window on the
  software composition path.

## Security — implemented

- Tracker blocking via `QWebEngineUrlRequestInterceptor` (fixed embedded
  EasyList/EasyPrivacy-style host list), with daily/weekly/30-day counters.
- HTTPS-First: `http://` main-frame loads auto-upgraded to `https://` (local
  hosts and IP literals exempt).
- Offline Safe Browsing: embedded + local blocklist, warning-page redirect,
  `QReadWriteLock`-guarded so lookups are safe from Chromium's IO thread.
- Encrypted local password vault: DPAPI on Windows, PBKDF2-HMAC-SHA256 keystream
  fallback; only per-entry lookups are exposed over the bridge.
- Isolated-world scripting (`ApplicationWorld`) for autofill and injected scripts.
- Private/incognito windows use a throwaway profile, skip session persistence,
  and install a dedicated non-recording interceptor (`privateInstance()`) so
  incognito traffic is never written into privacy.json.
- Clipboard and screen capture disabled in WebEngine settings.

## Corrections from this audit pass (applied)

1. Certificate-error handling — `handleCertificateError()` now calls
   `error.deferCertificateError()` (the `defer()` API does not exist) and shows
   the decision dialog window-modal, so the browser is locked until the user
   accepts or rejects the certificate.
2. Private-window tracker protection — incognito profiles install
   `TrackerBlocker::privateInstance()` (constructed with `m_incognito = true`)
   instead of a recording instance: identical blocking, HTTPS-First and
   Safe-Browsing protection, but no stats are recorded or persisted. The old
   mutable `setIncognito()` setter was removed in favor of the ctor flag.
3. Tracker blocklist is a fixed embedded list; there is no runtime user-override
   file. It is read on Chromium's IO thread from a set written only at
   construction, so it needs no lock.
4. HTTPS-First applies to both normal and private windows; localhost, *.local and
   IP literals are exempt, and upgraded URLs drop an explicit `:80` port.
5. Safe Browsing lookups are `QReadWriteLock`-guarded (`QReadLocker` in
   `isBlocked`); the optional local `safebrowsing.json` list and per-host
   allowlist are merged in `loadExtraList()` / `allow()`.
6. `getSafariUserAgent()` returns a platform-appropriate Safari UA (macOS gets
   the plain Apple UA; Windows/Linux append `BLACK/1.0`) and is used for both
   the main and private profiles.

## Feature Parity

Implemented: tabbed browsing, tab overview, pinned tabs, manual tab groups,
find-in-page, downloads, session restore, history, favorites/bookmarks (local),
reading list, sidebar, light/dark theming, keyboard shortcuts, macOS-style chrome,
password manager + autofill, extension manager.

Not implemented (honest): reader mode, PiP, translation, share sheet, per-site
settings, content-blocker extension API, passkeys/WebAuthn, and all Apple
ecosystem features (iCloud/Keychain, Apple Pay, Safari Notify Me, OAuth sign-in).

## Open Items

1. (done) Extension password-bridge isolation: the password-only QWebChannel
   bridge is exposed only in the private `kPasswordWorld` (autofill script) and
   the full bridge only on `qrc:/` internal pages; extension content scripts in
   `ApplicationWorld` can no longer reach the vault.
2. (done) Single-instance guard in main.cpp: a `QLockFile` in the profile
   directory prevents a second process from touching shared state; a secondary
   `BLACK.exe` forwards its command-line URLs over a `QLocalSocket` and exits,
   so profile data and session history cannot be clobbered.
3. Fix the three compositing hitches noted above.
